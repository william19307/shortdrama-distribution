## 0. 一句话定位与边界

**定位**：服务短剧版权方（客户）的海外发行"申请—审核—分成—数据—结算"一站式管理平台。

**做什么（范围内）**
1. 发行前内容管理：影片/剧集上传、素材与版权文件管理、发行计划申请。
2. 申请流转：剧集审核、分成配置、工单回传、修改重提、选平台。
3. 数据同步展示：各海外平台播放量/收益等表现数据的接口同步或人工同步，并在客户端展示。
4. 结算与提款：按结算周期发起结算、企业认证、发票上传、提款。
5. 防伪留证：带时间戳防伪水印截图，以工单形式供客户查看。

**不做什么（范围外）**
- ❌ 不负责向海外平台推送/分发内容（上架动作由运营+商务线下或在各平台后台完成，本平台只记录结果）。
- ❌ 不做视频转码/字幕翻译生产（只存储与管理成品素材）。
- ❌ 不做与海外平台之间的资金清算（只管理我方与客户之间的结算）。

## 2. 三端信息架构

> 三端 = **用户端（客户 Web）**、**运营端（运营/商务/财务工作台）**、**管理端（超管配置后台）**【暂按默认】。运营端与管理端可同一套后台按角色区分菜单。

### 2.1 用户端（一级菜单固定 3 个）

```
用户端
├── 数据详情                         ← 一级菜单 1
│   ├── 数据总览（总播放量/总收益[人民币预估，以结算单为准]/在发剧集数/发行平台数，数据截至时间）
│   ├── 剧集数据（按剧集 × 平台 × 日期：播放量、完播率、收益等；趋势图；导出）
│   ├── 平台数据（按平台汇总对比）
│   └── 结算与提款
│       ├── 可结算单列表（可多张合并）→ 发起结算申请
│       ├── 结算单详情（以运营录入并复核的人民币应结金额为准；附原币种收入、参考汇率/日期/来源及对客户说明；不展示保底金额与分成计算过程）
│       ├── 上传发票（财务人工审核）→ 提款（所选结算单合计 ≥ 最低提款额）
│       └── 提款记录
├── 视频存储库                       ← 一级菜单 2
│   ├── 影片列表（状态筛选：草稿/审核中/需修改/已通过/发行中/已下架）
│   ├── 上传影片（影片信息 + 剧集批量上传 + 封面/海报/预告 + 字幕 + 授权书/版权证明）
│   ├── 影片详情
│   │   ├── 剧集列表（逐集审核状态）
│   │   ├── 发行计划（首发：固定首批5家，不可剔除；二轮：手填目标平台）
│   │   ├── 各平台发行状态
│   │   └── 相关工单（审核结果 / 防伪截图）
│   └── 发起发行计划（入口也可在影片列表行操作）
├── 合同申请及列表                   ← 一级菜单 3
│   ├── 合同列表（发行合同/补充协议；状态：申请中/起草中/待签署/已生效/已到期）
│   ├── 发起合同申请（关联影片 + 发行计划 + 分成方案）
│   └── 合同详情（分成条款、保底条款、附件下载、签署记录）
│
└── 配套（非一级菜单：右上角头像/账户中心 + 关键流程中拦截引导）
    ├── 企业绑定与认证（营业执照、法人、对公信息）
    ├── 收款账户（对公账户，需与认证主体一致）
    ├── 授权书 / 版权证明（企业级资质库，上传影片时可复用）
    ├── 工单中心（审核结果工单、防伪截图工单、数据异议工单）——右上角铃铛
    └── 子账号管理（后续）
```

**拦截引导规则**
- 未企业认证：可上传影片、可看数据；**不可发起合同申请、不可提款**（提示去认证）。
- 未上传授权书/版权证明：不可发起发行计划。
- 未绑定收款账户：不可提交提款。

## 3. 核心流程图（mermaid）

### 3.1 端到端主流程

```mermaid
flowchart TD
    A[客户注册] --> B[上传影片/剧集<br/>+授权书/版权证明]
    B --> C{发行类型}
    C -- 首发 --> D[固定匹配首批5家平台<br/>ReelShort/DramaBox/ShortMax/FlexTV/GoodShort<br/>客户不可剔除]
    C -- 二轮 --> E[客户手动填写目标平台]
    D --> F[提交发行计划]
    E --> F
    F --> G[运营逐集审核]
    G --> H{审核结果}
    H -- 未通过 --> I[生成审核工单回传<br/>标注问题集数与原因]
    I --> J[客户修改后重新提交]
    J --> G
    H -- 通过 --> K[按平台配置分成<br/>保底/超保底/无保底]
    K --> K2[主管复核分成]
    K2 --> L[审核通过工单回传<br/>含分成方案]
    L --> M[运营+商务对接平台]
    M --> O[选平台发行<br/>平台侧上架由线下完成]
    O --> P[录入上架结果<br/>+防伪水印截图工单]
    P --> Q[数据同步<br/>API或每日06:00前手工]
    Q --> R[客户查看数据详情]
    R --> S0[结算周期到期<br/>按项目/客户配置,生成待录入结算单]
    S0 --> SE[运营录入人民币应结金额+备注<br/>参考:平台收入/参考换算/分成比例<br/>系统不计算]
    SE --> SR{财务或运营主管复核}
    SR -- 退回 --> SE
    SR -- 通过 --> S1{可申请结算单合计 ≥ 最低提款额?}
    S1 -- 否 --> S2[未达起提额<br/>保留,待与后续结算单合并申请]
    S2 --> S0
    S1 -- 是 --> S[客户发起结算申请<br/>可合并多张结算单]
    S --> T{企业已认证?}
    T -- 否 --> T1[企业认证] --> T
    T -- 是 --> U[财务核对提款申请]
    U --> V[客户上传发票]
    V --> W[财务人工审核发票并打款]
    W --> X[提款完成]
```

### 3.2 剧集审核与工单回传（泳道）

```mermaid
sequenceDiagram
    participant C as 客户
    participant S as 系统
    participant O as 运营专员
    participant M as 运营主管
    C->>S: 提交发行计划(影片+剧集+目标平台)

```

## 4. 状态机

### 4.1 发行计划（影片级）

```mermaid
stateDiagram-v2
    [*] --> 草稿
    草稿 --> 待审核: 客户提交
    待审核 --> 审核中: 运营领取
    审核中 --> 需修改: 存在驳回集
    需修改 --> 待审核: 客户修改后重新提交
    审核中 --> 分成配置中: 全部集通过
    分成配置中 --> 分成待复核: 运营提交
    分成待复核 --> 分成配置中: 主管退回
    分成待复核 --> 审核通过: 主管复核通过(工单回传)
    审核通过 --> 发行对接中: 运营+商务对接平台
    发行对接中 --> 发行中: 至少1个平台已上架
    发行中 --> 已下架: 全部平台下架/到期
    草稿 --> 已撤回: 客户撤回
    待审核 --> 已撤回: 客户撤回(未领取前)
    已下架 --> [*]
    已撤回 --> [*]
```

### 4.2 单集审核状态

`待审核 → 审核中 → 通过 / 驳回`；`驳回 → 已修改待复审 → 审核中`。已通过的集在重提时**不重复审核**（除非客户替换了该集素材）。

### 4.3 平台发行（剧集 × 平台）

```mermaid
stateDiagram-v2
    [*] --> 待对接
    待对接 --> 对接中: 商务发起
    对接中 --> 平台已拒绝: 平台不接
    对接中 --> 待上架: 平台确认
    待上架 --> 已上架: 录入上架链接/ID+防伪截图
    已上架 --> 已下架: 下架/授权到期
    平台已拒绝 --> [*]
    已下架 --> [*]
```

### 4.4 分成配置（剧集 × 平台）

| 模式 | 必填字段（运营端） | 客户端可见 | 说明 |
|---|---|---|---|
| 保底 | 保底金额、币种、保底期、客户分成比例 | 模式标签、分成比例 | 平台给保底，期内收益不超过保底按保底结 |
| 超保底 | 保底金额、保底内比例、**超出部分**客户分成比例 | 模式标签、各段分成比例 | 超过保底部分按另一比例分 |
| 无保底 | 客户分成比例 | 模式标签、分成比例 | 纯按收益分成 |

- **保底金额对客户不可见【已定】**：客户端页面、导出、工单、合同申请列表、接口返回均不得含保底金额字段（接口层脱敏，不只是前端隐藏）。
- **分成配置仅作参考，不参与系统计算【已定】**：保底金额、保底期、各段分成比例在「应结金额录入」页作为参考信息展示给运营；系统不计算应结金额、不做保底摊销/冲抵/结转，应结金额由运营手工录入（见 6.8）。
- 保底金额按合同原币种记录，仅运营端可见。
- 「项目」口径：一个客户 × 一部影片 × 一个发行轮次（首发/二轮）对应的发行合作；结算周期、汇率配置均为客户级默认、项目级可覆盖【暂按默认】。

### 4.5 工单

`已创建 → 待客户查看 → 客户已读 → (客户回复/异议 → 处理中 → 已解决) → 已关闭`
工单类型：审核结果、防伪截图、数据异议、结算异议（客户对应结金额有异议时发起，运营修改金额须重新复核）。

### 4.6 每日同步任务

任务的数据日期 = 当天 − 平台口径（T-1/T-2，按平台配置）。`待同步 → 同步中 → 已完成 → 已发布`；`同步中/待同步 → 已超时(06:00) → 已完成(超时完成，留记录)`；`已发布 → 修正中 → 已发布(新版本)`。

### 4.7 企业认证

`未认证 → 审核中 → 已认证 / 认证驳回 → 审核中`；主体变更 → `变更审核中`（审核期间保留原认证，冻结提款）。

### 4.8 结算单

```mermaid
stateDiagram-v2
    [*] --> 待录入: 结算周期结束,系统生成结算单
    待录入 --> 待复核: 运营录入人民币应结金额+备注
    待复核 --> 待录入: 复核退回(填原因)
    待复核 --> 无需结算: 复核通过且应结金额为0
    无需结算 --> [*]
    待复核 --> 待申请: 复核通过且可申请合计≥最低提款额
    待复核 --> 未达起提额: 复核通过但合计<最低提款额
    未达起提额 --> 待申请: 后续结算单复核后合计达标
    未达起提额 --> 待复核: 运营修改金额(留痕)
    待申请 --> 待复核: 客户申请前运营修改金额(留痕)
    待申请 --> 核对中: 客户发起(可合并多张,需已认证)
    核对中 --> 待申请: 财务退回
    核对中 --> 待开票: 财务确认
    待开票 --> 发票审核中: 客户上传发票(财务人工审核)
    发票审核中 --> 待开票: 发票不符
    发票审核中 --> 打款中: 审核通过
    打款中 --> 已到账: 上传打款凭证
    已到账 --> [*]
```

- 说明：应结金额为 0 的结算单复核通过后归档为「无需结算」【暂按默认】。
- 「核对中」起金额锁定；之后如需改金额，须财务退回到「待申请」，运营修改后重新复核，全程留痕。

### 4.9 汇率配置与参考换算【已定】

```mermaid
stateDiagram-v2
    [*] --> 草稿: 运营主管/财务新建或修改取值方式
    草稿 --> 待复核: 提交(填写变更原因)
    待复核 --> 草稿: 复核退回
    待复核 --> 已生效: 复核通过(到生效时间)
    已生效 --> 已失效: 新版本生效
    已失效 --> [*]
```

- 汇率配置以**版本**管理，每个版本不可修改，只能新建版本替代；变更日志记录 变更人、时间、变更前后值、原因、复核人。
- 结算单生成及运营录入时，系统按生效配置为每一行原币收入生成**参考换算快照**（见 6.7），供运营录入参考与客户对账参考；**最终以运营录入并复核的人民币应结金额为准**，参考换算与录入金额不一致时不阻断流程，仅提示差额【暂按默认】。结算单进入「核对中」后快照与金额一并锁定。
- 缺少所需汇率时，参考面板提示「缺少汇率，参考换算不可用」，不阻断录入【暂按默认】。

## 6. 关键页面要点

### 6.1 手工录入/导入页（运营端）
- 顶部：平台选择、数据日期（按该平台配置的口径 T-1/T-2 自动带出，可手改补录历史日期）、该平台今日任务状态与 **距 06:00 倒计时**。
- 录入表格：行=该平台在发剧集（自动带出），列=指标（播放量、完播率、新增订阅/解锁、收入、币种…，指标字典按平台可配）。支持复制粘贴整块。
- 导入：下载模板（预填剧集ID与平台剧集ID）→ 上传 → 校验预览（必填、类型、负数、环比 ±300% 异常提示、重复）→ 错误行可就地修改 → 确认入库。
- 每次提交记录 操作人、时间、来源（手工/导入/API）、**附原始报表截图/文件**（可直接走水印相机）。

### 6.2 防伪水印截图（水印相机模式）
- 入口：运营端工单内"拍摄/截图取证"，支持上传截图或网页内截屏。
- **服务端**叠加水印（客户端不可伪造）：UTC+8 时间戳【暂按默认】（精确到秒，取服务器时间）、操作人、工单号、平台名、剧集名、图片 SHA-256 短哈希；平铺半透明暗纹 + 角标明文。
- 原图与水印图同时存档，原图仅运营可见；水印图通过工单推送客户。
- 用途：上架证明、平台后台数据证明、下架证明。

### 6.3 发行计划发起（用户端）
- 首发：固定匹配首批5家平台（ReelShort / DramaBox / ShortMax / FlexTV / GoodShort），只读展示，**客户不可剔除**【已定】；名单实时读取运营端「平台名单配置」，提交时快照保存到发行计划。
- 二轮：必须手动填写目标平台（从平台库选择，库中没有的可自由填写，提交后由商务补录平台库）；需说明已发行平台以避免冲突。

### 6.4 平台名单配置（运营端，新增）【已定】
- 列表字段：平台名称、地区、状态（启用/停用）、是否首批（首批标记+排序）、同步方式（API/手工）、**数据日期口径（T-1/T-2）**、责任运营、更新人/时间。
- 首批名单初始化：ReelShort / DramaBox / ShortMax / FlexTV / GoodShort。增删首批平台需运营主管确认；只影响之后新提交的首发计划，已提交计划按提交时快照。
- 停用平台：不能被新计划选择；已上架记录与历史数据保留。
- 口径修改：仅影响次日起生成的同步任务，变更留痕。

### 6.5 结算周期配置（运营端）【已定】
- 配置层级：客户级默认 → 项目级覆盖。
- 字段：结算周期（自然月/季度/自定义天数/自定义起止日，不固定）、首个周期起始日、生效日期、备注。（v0.4 起不再配置跨期结转规则）
- 周期结束时系统生成「待录入」结算单并提醒责任运营。
- 最低提款额读取管理端全局配置（客户端在提款页提示「满 X 元可提」）。
- 保存后生成配置版本；只对未生成的结算单生效。

### 6.6 发票人工审核（运营端·财务）【已定】
- 左侧发票图片/PDF 预览，右侧结算单信息；逐项核对清单：抬头=认证主体、税号、金额=结算单人民币金额、税率、开票日期、票面清晰。
- 结果：通过 / 驳回（原因模板 + 备注），驳回通过工单通知客户重传。

### 6.7 汇率配置（运营端·结算管理，新增）【已定】
**A. 取值方式配置（版本化）**
| 字段 | 说明 / 可选值 |
|---|---|
| 配置编号 / 版本号 | 系统生成，版本只增不改 |
| 适用范围 | 全局默认；可按客户/项目覆盖【已定】 |
| 币种对 | 原币种 → CNY（如 USD→CNY、EUR→CNY…），可多行 |
| 汇率来源 | 中国人民银行人民币汇率中间价 / 中国外汇交易中心 / 指定银行牌价（填写银行与买入/卖出/中间价）/ 合同约定 / 手工录入 |
| 汇率类型 | 浮动（按取值日期规则每次取值）/ 固定（填写固定汇率值 + 有效期） |
| 取值日期规则 | 结算周期最后一个自然日 / 最后一个工作日 / 结算单生成日 / 收入数据日期逐日换算 / 周期内日均值 / 指定日期；节假日无汇率时：取前一个有汇率日 |
| 精度与舍入 | 汇率保留位数（默认 4 位）、金额保留 2 位、舍入方式（四舍五入/截断）、换算粒度（逐笔换算后汇总 / 汇总后换算） |
| 生效时间 | 只影响生效后生成的参考换算 |
| 变更原因 / 复核人 | 必填；提交后须另一人复核（运营主管 ↔ 财务互审） |

**B. 汇率记录库**：币种对、汇率日期、汇率值、来源、获取方式（手工/导入/自动）、录入人、录入时间、附件（来源截图，可走水印相机）。已被结算单引用的记录不可修改，只能作废并新增，作废需原因。

**C. 参考换算快照（结算单明细每行写入，仅作参考）**：原币种、原币金额、汇率值、汇率日期、汇率来源、汇率记录 ID、汇率配置版本号、舍入规则、参考人民币金额、换算时间。最终金额以 6.8 运营录入为准【暂按默认】。

**D. 追溯查询**：按结算单 / 客户 / 项目 / 平台 / 剧集 / 汇率记录反查，导出 Excel；配置变更日志展示前后对比。

**E. 客户端展示【已定】**：结算单与提款以**运营录入并复核的人民币应结金额为准**；明细附原币收入及参考汇率值、汇率日期、汇率来源，并注明「参考汇率依据合同及我方汇率配置，结算以应结金额为准」；如运营填写了「对客户说明」一并展示。数据详情中的收益显示原币种 + 人民币预估（按当前生效配置估算，以结算单为准）。

### 6.8 应结金额录入与复核（运营端·结算管理，新增）【已定】
**A. 录入页**
- 左侧**参考面板**（只读，不参与计算）：结算周期、项目/剧集/平台、各平台原币收入（来自数据同步）、参考换算人民币（按汇率配置，含汇率/日期/来源）、分成模式与比例、保底金额与保底期（仅运营端可见）、历史结算单金额。
- 右侧**录入区**：人民币应结金额（必填，2 位小数，可为 0）、可选按平台/剧集分行录入（合计自动汇总为应结金额）、内部备注（必填，说明依据）、对客户说明（选填，客户可见）、附件（选填，如对账截图）。
- 与参考换算合计偏差超过阈值（默认 ±5%，管理端可配）时黄色提示，不阻断【暂按默认】。
- 提交后进入「待复核」。

**B. 留痕**
| 字段 | 说明 |
|---|---|
| 录入人 / 录入时间 | 首次录入记录 |
| 修改记录 | 每次修改：修改人、修改时间、字段、修改前值、修改后值、修改原因（必填） |
| 复核记录 | 复核人、复核时间、结果（通过/退回）、意见 |
| 不可删除 | 记录只增不删；结算单进入「核对中」后金额锁定 |

**C. 复核页**：财务或运营主管均可复核，**录入人不得复核本人录入**；展示与参考换算的差额、修改历史对比；退回须填原因。

**D. 最低提款额与不足额处理【暂按默认】**：复核通过后，系统按客户维度汇总所有「未达起提额 / 待申请」结算单金额；合计 < 最低提款额时置为「未达起提额」，客户端可见金额但不可申请；后续结算单复核后合计达标，全部转「待申请」，客户可勾选多张合并申请，一次开票、一次打款。系统不做任何自动结转计算。

## 8. 非功能要点
- 视频存储：对象存储 + 分片上传；单文件 ≤ 10GB【暂按默认】；预览用低码率代理文件。
- 安全：素材下载签名 URL + 有效期；客户数据隔离；敏感操作（分成、打款、数据修正）全量日志。
- 时间：所有截止/水印时间统一 UTC+8【暂按默认】；海外平台数据日期按平台时区换算后标注。
- 金额：结算统一人民币【已定】；应结金额由运营手工录入并复核，系统不计算【已定】；原币收入与参考换算快照同时存储，金额用定点小数（decimal），禁止浮点；应结金额录入/修改/复核、汇率配置全程留痕。

## 9. 可优化点（每条：对我方价值 / 对客户价值）

| # | 优化点 | 对我方的价值 | 对客户的价值 |
|---|---|---|---|
| 1 | **上传即自动质检**（分辨率、时长、黑帧、字幕缺失、集数连续性） | 运营审核工时下降，驳回往返减少 | 提交前就发现问题，缩短上线等待 |
| 2 | **驳回原因结构化模板 + 时间点批注** | 审核口径统一，新运营上手快，可统计高频问题 | 一眼看懂哪集哪秒要改，改一次过 |
| 3 | **仅复审驳回集** | 重复审核量大幅减少 | 修改后通过更快 |
| 4 | **分成方案模板+批量套用** | 配置效率高、减少错配风险 | 分成条款一致透明，减少合同扯皮 |
| 5 | **Excel 导入模板预填剧集ID + 环比异常校验** | 06:00 前完成率提升，录错可提前拦截 | 数据更准、更新更及时 |
| 6 | **"数据截至时间"与更新中提示** | 降低客户催问与客服压力 | 清楚数据新鲜度，不误判表现 |
| 7 | **逐平台替换为 API 同步** | 释放每日手工人力，消除超时风险 | 数据更实时，可更早决策二轮发行 |
| 8 | **服务端防伪水印 + 原图哈希存证** | 争议时有可靠证据，降低纠纷与法律风险 | 对上架/数据真实性放心，增强信任 |
| 9 | **平台表现对比 + 二轮发行推荐** | 提升二轮发行转化，增加分成收入 | 用数据选平台，提升收益 |
| 10 | **录入金额与参考换算偏差提示 + 发票信息预填与校验** | 降低手工录入错误与复核成本，退票次数减少 | 应结金额更准确，开票一次通过，回款更快 |
| 11 | **资质到期提醒（授权书/版权证明）** | 规避授权过期仍在发行的合规风险 | 提前续约，不中断收益 |
| 12 | **子账号分权（上传/数据/财务）** | 对接人清晰，减少账号共用带来的安全问题 | 团队协作方便，权责分离 |
| 13 | **订阅日报/周报邮件** | 提高客户活跃与续约意愿 | 不登录也能掌握表现 |
| 14 | **在线电子签** | 合同周期缩短、归档规范 | 免邮寄，签约更快 |
| 15 | **对接权威汇率源自动抓取 + 汇率透明展示** | 免手工录汇率、消除录错风险，有据可查减少汇率争议 | 能核对每笔换算依据，结算金额可信 |
